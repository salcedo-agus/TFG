<objective>
Make the ctypes/GUI path initialize `Rocket%rm_L` exactly like the console path, so GUI Run produces real, finite mass values.

Purpose: G-01-2 root cause is that `C_Interface.f90:run_staging` builds `Rocket` with only delta_v/ISP/k_s and calls `STAGING` directly; the sole `rm_L` write site (`Payload_Mass_calc.f90:19`) is reachable only from `Main.f90:11` (console). `Staging.f90:86` (`m_0 = rm_L * product`) then multiplies uninitialized stack memory into every stage mass; the GUI's NaN guard (`gui.py:573`) renders those as "—" — the user-visible "null results". The fix mirrors the console formula on the ctypes path (identical numbers both paths) and adds a default-init as defense-in-depth.

Output: A rebuilt `build/librocket.dll` where the GUI path applies `rm_L = payload_mass + 0.0755*payload_mass + 50` before staging; GUI Results show real masses; console output unchanged.
</objective>
