# Phase 1 — UI Design Contract: Centralized 3-Tab GUI

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Context:** PyQt6 6.11.0 desktop engineering app. This contract governs the restructuring of `SRC/gui/gui.py` `MainWindow` (currently a left-input / right-results split, `gui.py:712-815`) into a centralized 3-tab workbench. The splash screen (`SplashScreen`/`AppWindow`, `gui.py:582-700`, `990-1019`) and the global `STYLE` QSS string (`gui.py:134-312`) are preserved **as-is** (D-13); this contract extends `STYLE` with tab-bar and radio-button rules and defines tokens every new widget must honor. No Fortran changes (phase boundary), no source-code modification by this spec.

## Layout Structure & Interaction Contract

### Tab shell (D-01, D-02)

`QTabWidget` set as `MainWindow.setCentralWidget`. Tab order is contractual:

| Index | Title (exact string) | Content |
|-------|----------------------|---------|
| 0 | **Results** | Central/home surface: summary, minimum indicator, divider, per-stage cards, Save Results, empty state |
| 1 | **Setup** | Relocated header, Mission Parameters group, stage input widgets (verbatim), Run button |
| 2 | **Vehicle Configuration** | Diameter-mode radios + conditional input box (new) |

Rules: `addTab` order fixed (0/1/2); tabs never reordered, hidden, or renamed. Import `QTabWidget` (`gui.py:9-15` currently lacks it). Tabs live inside the existing `QScrollArea` pattern — each tab page is a `QScrollArea` + inner widget + `QVBoxLayout` with `addStretch()` bookends (existing container pattern, `gui.py:720-727`, `803-815`).

### Results tab (index 0)

1. **Summary header**: "Total Initial Mass: {total_initial_mass:,.1f} kg" — 14px TEXT_PRI with the value in 22px/700 ACCENT (existing rich-text pattern, `gui.py:948-955`).
2. **Minimum indicator** (verbatim logic, `gui.py:957-963`): "✔ Minimum confirmed" GREEN / "✘ Minimum not confirmed — check your inputs" ACCENT2, 12px/600.
3. **Divider** (`QFrame#divider`).
4. **Stage cards**: existing `ResultCard` 2-column metric grid **extended by exactly 2 rows** (research Open Question 4 recommendation — keep cards, add rows):

   | Grid row | Col 0 | Col 1 |
   |----------|-------|-------|
   | 0 | Initial Mass (m₀) — kg | Final Mass (m_f) — kg |
   | 1 | Propellant Mass (m_p) — kg (ACCENT2) | Structure Mass (m_s) — kg |
   | 2 | Mass Ratio (k_m) — ACCENT | Payload Ratio (k_L) — ACCENT |
   | 3 | Struct. Coeff. (k_s) | Exhaust Vel. (ν_e) — km/s |
   | **4 (new)** | **Stage ΔV — km/s** | **Diameter — m** |
   | **5 (new)** | **Length — m** | **Volume — m³** |

   Value formatting contract: masses `%,.1f kg`; ratios `%.4f`; ν_e `%.4f km/s`; ΔV `%.2f km/s`; diameter/length `%.2f m`; volume `%.2f m³`. **Unavailable values render "—" in TEXT_DIM** (partial population, user-approved): per-stage ΔV and all geometry until Phase 2. When any "—" is rendered, the partial-state hint appears once below the placeholder/empty state.
5. **Save Results** button (`print_btn` style, verbatim) pinned at bottom of the cards, above `addStretch()`. Enabled only after a successful run (`gui.py:981` logic preserved). Modal save dialog title "Save Results", filter "Text Files (*.txt)".
6. **Empty state** (never-run or inputs changed): centered "Run the analysis to see results here." at layout index 0 — `_show_empty_state()` / `_clear_results()` pattern preserved, now targeting the Results tab layout.

### Setup tab (index 1)

1. **Header**: "ROCKET STAGING" 20px/800 + subtitle "Multi-stage propulsion optimizer" 12px TEXT_SEC + divider (verbatim, `gui.py:732-739`).
2. **Mission Parameters** group (`QGroupBox` title "MISSION PARAMETERS", verbatim style):

   | Row | Label | Widget |
   |-----|-------|--------|
   | 0 | **"Orbit Height (km)"** — NEW | `QDoubleSpinBox`, range **100.0–2000.0**, decimals 1, single step 10.0, default **500.0**. Bounded per V5 input-validation control (research Security Domain). Stored for Phase 2 pipeline handoff. |
   | 1 | "Payload Mass (kg)" | `pl_spin` verbatim: 1.0–1,000,000, default 5000.0, decimals 1, step 100.0 (`gui.py:755-760`) |
   | 2 | "Number of Stages" | `n_stages_spin` verbatim: 1–3, default 3 (`gui.py:763-766`) |
   | 3 | **"ΔV (auto)" — read-only** | `QLabel` showing the internally computed ΔV `{:.2f} km/s`, styled TEXT_SEC 12px. **Not editable, no spinbox** (D-10). Value derives from orbit height (research Open Question 1: interim Python `V_circ` computation recommended; exact formula is planner's call — the *contract* is: read-only, always present, updates on orbit-height change, feeds `run_staging` and the export header). |

   The old `dv_spin` (rows 0 of the old grid) is **removed** — no ΔV input anywhere in the app (GUI-05 check).
3. **Stage inputs container** (`stages_container`): `StageInputWidget`s verbatim (D-08) — propellant combo + cycle combo (`NoScrollComboBox`), ISP slider group ("Specific Impulse — ISP (s)"), k_s slider group ("Structural Coefficient — k_s"), range/value labels, invalid-state handling (`gui.py:319-528`). `_rebuild_stage_inputs` keeps operating on this container.
4. **Run button** verbatim (`gui.py:780-795`): "▶ Run Staging Analysis", `ready` property + green state, disabled look otherwise. `_update_run_button` logic unchanged.
5. Signal wiring preserved across tabs (research Pitfall 3): `pl_spin`/`n_stages_spin`/`orbit_height` `valueChanged` → `_on_inputs_changed` (clears Results tab + disables Save); `validity_changed` → `_update_run_button` + `_on_inputs_changed`.

### Vehicle Configuration tab (index 2) — new

1. **Header**: "VEHICLE CONFIGURATION" 20px/800 + subtitle "Diameter sizing mode" 12px TEXT_SEC + divider (mirrors Setup header pattern).
2. **"DIAMETER MODE"** `QGroupBox` with **3 `QRadioButton`s** (mutually exclusive; radios chosen over a combo so all three modes are visible and the reveal/hide interaction is explicit — GUI-06 checkable at a glance):

   | Radio label (exact) | Stored int | Semantics (Fortran mirror) |
   |---------------------|-----------|----------------------------|
   | "Statistically determined" | **1** | Per-stage regression curves; monotonicity pass (`Geometry_calc.f90:92-105`) — **default checked** (mirrors `config.txt` `Diameter_setup = 1`) |
   | "Constant" | **2** | All stages take `maxval` of statistical diameters |
   | "User-specified" | **3** | All stages take the entered value (`user_defined_diameter` semantics) |

   Each radio followed by its helper description line (11px TEXT_SEC, see Copywriting contract). Mode value stored as `int` 1/2/3 on MainWindow state for Phase 2 handoff (research Pitfall 8 — do NOT wire into `run_staging` in Phase 1).
3. **User-specified diameter box** (D-12, GUI-07): `QDoubleSpinBox` labeled "User-Specified Diameter (m)" — range **0.5–20.0**, decimals 2, single step 0.1, default **2.00** (mirrors `config.txt` `User_defined_diameter = 2.0`). Placed directly under the mode group. **Visibility contract: hidden (`setVisible(False)`) when modes 1 or 2 are selected; shown when mode 3 is selected.** Toggle wired to radio `toggled` signals; value persists across tab switches and mode toggles (widgets are never rebuilt).
4. This tab has **no Run dependency** — pure configuration surface.

### Cross-tab interaction contract

- **Run → Results**: on successful `_run`, results render into the Results tab layout and the app **auto-switches to tab 0** (`setCurrentIndex(0)`) so the user sees the output (new behavior required by the tabbed layout — results are no longer visible while on Setup).
- **Input change → invalidation**: any Setup input change clears Results content, restores empty state, disables Save; the user stays on the current tab (no forced navigation).
- **State persistence**: tabs are built once; switching tabs never rebuilds or resets widget state (sliders, spins, radios, results all persist until invalidated).
- **Splash**: untouched (D-13) — `AppWindow` stack + 600 ms InOutQuad fade preserved exactly.
- **Solver**: remains a blocking call on the UI thread (research A6 recommendation); no new thread machinery in this phase.
